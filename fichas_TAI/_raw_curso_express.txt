Traducción direcciones NAT
Source NAT: Se cambia la dirección IP de origen. Ejemplo: cuando usamos una IP privada en una red local y establecemos una conexión con un
equipo de Internet. Un equipo de la red (normalmente el gateway) se encarga de cambiar la IP privada origen por la IP pública, para que el equipo
de Internet pueda contestar. También es conocido como IP masquerading. Podemos distinguir dos casos:
- SNAT estático (Static NAT): la IP pública que sustituye a la IP origen es estática.
- SNAT dinámico o MASQUERADE: la IP pública que sustituye a la IP origen es dinámica (habitual en conexiones domésticas).
Destination NAT o port forwarding: se utiliza cuando tenemos algún servidor en una máquina detrás del dispositivo de NAT. Será un equipo
externo el que inicie la conexión, ya que solicitará un determinado servicio y el dispositivo de NAT debe modificar la dirección IP destino. Ej:
Servidor web.
PAT (Port Address translation): Modifica el puerto (origen o destino) en lugar de la IP. Ej: Peticiones web al 80 -> 8080.

Protocolos de enrutamiento
- Los algoritmos de exterior (EGP) se dan entre sistemas autónomos (AS), entre ISPs. El número AS lo asigna IANA.
- Vector distancia: intercambio con los vecinos.
- Estado enlace: foto completa de la red. Más óptimo.
- OSPF se puede descomponer en áreas (una de ellas llamada Backbone) y usa las siguientes direcciones multicast 224.0.0.5 y 224.0.0.6.
- RIPv2 manda por multicast la tabla de routing a todos los routers adyacentes mediante multicast a la direccion 224.0.0.9. RIPv1 usaba broadcast.
Los routers usan RIP.
- Protocolos que soportan VLSM: OSPF, RIPv2,IS-IS y EIGRP.
Protocolo de control ICMPv4: se encapsula directamente sobre IP, por lo que es enrutable. Cabecera de 4 bytes.
- Los tipos 8/0 se usan en el comando ping y además el 11 en traceroute.
- El tipo 3 con code=4 “Fragmentation Needed” se usa para el descubrimiento de MTU.
Protocolo de transporte TCP
- No usa direcciones, usa puertos. Es garantista. Cabecera de 20 a 60 bytes.
- El numero de puerto indentifica a una aplicación en uno de los extremos (Socket).
• Well Known Ports o System Ports: 0 - 1023. Asignados por IANA.
• Registered Ports o User Ports: 1024 - 49151.
• Dynamic Ports o Private Ports: 49152 - 65535.
- Proceso de establecimiento de conexión (handshake) previo al envío de información. Se determinan los números de secuencia que usará cada
extremo en esa sesión. En el primer segmento SYN se establece Window Scale, MSS, ECN Capable, etc. El tamaño de ventana es muy pequeño, así
que se usa un factor multiplicador (Window scale).
- Proporciona transporte fiable extremo a extremo (ACK con un numero de secuencia). Opción SACK para confirmar un bloque de secuencias “sin
orden” cuando hay pérdidas de paquetes.
- Mecanismo de control de flujo basado en mecanismo de ventana ”de recepción” deslizante (cada ACK viene con el campo Window Size
informado). Window Size = 0 si el equipo está saturado y no puede recibir más información.
- MSS: Tamaño máximo de segmento que el destino está dispuesto a recibir. Número de bytes que estamos dispuestos a recibir en un único
segmento (relacionado con la MTU para evitar fragmentación en IP). Se informa en la PDU. Cada extremo maneja un MSS independiente.
MSS = MTU – IPHeader – TCPHeader.
Flags importantes
URG: Urgent. Los datos del paquete deben ser procesados inmediatamente.
PSH: Push. Envía inmediatamente todos los datos almacenados en el buffer.
FIN: Finish. No harbá más transmisiones.
ACK: Acknowlegment. Reconoce la recepción de un paquete.
RST: Reset. Resetea una conexión.
SYN: Synchronize. Inicia una conexión entre hosts.

Subnetting: Método VLSM
1.- Ordenar las redes de modo decreciente por número de host, de más a menos hosts.
2.- Calculamos el número de bits necesarios para direccionar el número de hosts de cada una de las redes, teniendo en cuenta la red y el broadcast.
3.- Los bits de la derecha son para el host y los que sobran hasta la máscara son para subredes.

oprotected: puede usarse en la herencia, pero no fuera, a menos que esté dentro del mismo paquete. Protegido para la herencia y para el paquete.

Paradigmas de programación: formas de clasificar los lenguajes de programación en función de sus características. Los paradigmas de programación comunes son:
• Imperativo: el programador dice a la máquina qué hacer en un orden.
• Procedimental: agrupa las instrucciones en procedimientos.
• Orientado a objetos: agrupa las instrucciones con la parte del estado en objetos. Suelen ser imperativos.
• Declarativo: el programador declara el resultado deseado.
• Funcional: el resultado deseado se declara como el valor de una serie de aplicaciones de función.
• Lógico: el resultado deseado se declara como la respuesta a una pregunta sobre un sistema de hechos y reglas.
• Matemático: el resultado deseado se declara como la solución de un problema de optimización.
• Reactivo: el resultado deseado se declara con flujos de datos y la propagación del cambio.

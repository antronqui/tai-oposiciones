Detalles del test (no siempre se cumplen pero vienen bien):
- Si se duda entre las opciones y son definiciones, tirar por la respuesta
larga.
- Si se van dando dos opciones similares, probablemente sea una de las
dos, incluso las otras pueden dar pistas.
- Las de cálculos o las sabes o mejor no contestarlas.
- Si algunas parecen muy fáciles o literales, probablemente es porque lo
sean.
- Pocas veces van a pillar en las preguntas.
- Hacer el supuesto ya pensado de antes de hacer el examen.
- En leyes las fechas casi siempre son en días hábiles.
- Las respuestas con cosas absolutas como no se puede/imposible/sólo
suelen ser falsas.
- Hacer el test del año anterior (puedes encontrarte alguna igual o muy
parecida) y, el supuesto de tres convocatorias pasadas (lo mejor es
hacer todos los test anteriores).
- En las preguntas de reserva puedes tener pistas sobre otras preguntas.
- Responder en torno a 55 en la primera parte.
- Llevar el supuesto muy bien, responder a casi todas.

- 159: El Tribunal Constitucional se compone de 12 miembros
nombrados por el Rey; de ellos, cuatro a propuesta del Congreso

designados por un período de nueve años y se renovarán por

judicial. Los miembros del Tribunal Constitucional serán
independientes e inamovibles en el ejercicio de su mandato.

- De los conflictos de competencia entre el Estado y las

- De las demás materias que le atribuyan la Constitución o

Igualdad efectiva entre mujeres y hombres 3/2007:
- El principio de igualdad de trato entre mujeres y hombres supone la
ausencia de toda discriminación, directa o indirecta, por razón de sexo,
y, especialmente, las derivadas de la maternidad, la asunción de
obligaciones familiares y el estado civil.
- La igualdad de trato y de oportunidades entre mujeres y hombres es
un principio informador del ordenamiento jurídico y, como tal, se
integrará y observará en la interpretación y aplicación de las normas
jurídicas.
- Discriminación directa por razón de sexo: Situación en que se
encuentra una persona que sea, haya sido o pudiera ser tratada, en
atención a su sexo, de manera menos favorable que otra en situación
comparable.
- Discriminación indirecta por razón de sexo: Situación en que una
disposición, criterio o práctica aparentemente neutros pone a personas
de un sexo en desventaja particular con respecto a personas del otro,
salvo que dicha disposición, criterio o práctica puedan justificarse
objetivamente en atención a una finalidad legítima y que los medios
para alcanzar dicha finalidad sean necesarios y adecuados.
- Acoso sexual: Comportamiento, verbal o físico, de naturaleza sexual
que tenga el propósito o produzca el efecto de atentar contra la
dignidad de una persona, en particular cuando se crea un entorno
intimidatorio, degradante u ofensivo.
- Acoso por razón de sexo: Comportamiento realizado en función del
sexo de una persona, con el propósito o el efecto de atentar contra su
dignidad y de crear un entorno intimidatorio, degradante u ofensivo.
23
- Discriminación por embarazo o maternidad: Constituye
discriminación directa por razón de sexo todo trato desfavorable a las
mujeres relacionado con el embarazo o la maternidad.
- Acciones positivas: Medidas específicas en favor de las mujeres para
corregir situaciones patentes de desigualdad de hecho respecto de los
hombres.
- Cualquier persona podrá recabar de los tribunales la tutela del derecho
a la igualdad entre mujeres y hombres, de acuerdo con lo establecido
en el artículo 53.2 de la Constitución, incluso tras la terminación de la
relación.
- La persona acosada será la única legitimada en los litigios sobre acoso
sexual y acoso por razón de sexo.
- Presencia o composición equilibrada: Presencia de mujeres y
hombres de forma que, en el conjunto a que se refiera, las personas de
cada sexo no superen el sesenta por ciento ni sean menos del cuarenta
por ciento.
- El Gobierno, en las materias que sean de la competencia del Estado,
aprobará periódicamente un Plan Estratégico de Igualdad de
Oportunidades, que incluirá medidas para alcanzar el objetivo de
igualdad entre mujeres y hombres y eliminar la discriminación por razón
de sexo.

Personas en situación de dependencia 39/2006:
- Grados de dependencia:
- I. Dependencia moderada: Cuando la persona necesita ayuda
para realizar varias actividades básicas de la vida diaria, al
menos una vez al día o tiene necesidades de apoyo intermitente
o limitado para su autonomía personal.
- II. Dependencia severa: Cuando la persona necesita ayuda para
realizar varias actividades básicas de la vida diaria dos o tres
veces al día, pero no quiere el apoyo permanente de un cuidador
o tiene necesidades de apoyo extenso para su autonomía
personal.
26
- III. Gran dependencia: Cuando la persona necesita ayuda para
realizar varias actividades básicas de la vida diaria varias veces
al día y, por su pérdida total de autonomía física, mental,
intelectual o sensorial, necesita el apoyo indispensable y
continuo de otra persona o tiene necesidades de apoyo
generalizado para su autonomía personal.
- El grado de dependencia será revisable, a instancia del interesado, de
sus representantes o de oficio por las Administraciones públicas
competentes, por alguna de las siguientes causas:
- Mejoría o empeoramiento de la situación de dependencia.
- Error de diagnóstico o en la aplicación del correspondiente
baremo.
Derechos de las personas discapacitadas 1/2013:
- Discriminación directa: Es la situación en que se encuentra una
persona con discapacidad cuando es tratada de manera menos
favorable que otra en situación análoga por motivo de o por razón de su
discapacidad.
- Discriminación indirecta: Existe cuando una disposición legal o
reglamentaria, una cláusula convencional o contractual, un pacto
individual, una decisión unilateral o un criterio o práctica, o bien un
entorno, producto o servicio, aparentemente neutros, puedan ocasionar
una desventaja particular a una persona respecto de otras por motivo
de o por razón de discapacidad, siempre que objetivamente no
respondan a una finalidad legítima y que los medios para la
consecución de esta finalidad no sean adecuados y necesarios.
- Discriminación por asociación: Existe cuando una persona o grupo
en que se integra es objeto de un trato discriminatorio debido a su
relación con otra por motivo o por razón de discapacidad.

Tratamiento de datos UE 2016/679:
- Los datos personales serán:
- Tratados de manera lícita, leal y transparente en relación con el
interesado («licitud, lealtad y transparencia»).
- Recogidos con fines determinados, explícitos y legítimos, y no
serán tratados ulteriormente de manera incompatible con dichos
fines, el tratamiento ulterior de los datos personales con fines de
archivo en interés público, fines de investigación científica e
histórica o fines estadísticos no se considerará incompatible con
los fines iniciales («limitación de la finalidad»);
- Adecuados, pertinentes y limitados a lo necesario en relación con
los fines para los que son tratados (minimización de datos).
- Exactos y, si fuera necesario, actualizados; se adoptarán todas
las medidas razonables para que se supriman o rectifiquen sin
dilación los datos personales que sean inexactos con respecto a
los fines para los que se tratan («exactitud»).
28
- Mantenidos de forma que se permita la identificación de los
interesados durante no más tiempo del necesario para los fines
del tratamiento de los datos personales; los datos personales
podrán conservarse durante períodos más largos siempre que se
traten exclusivamente con fines de archivo en interés público,
fines de investigación científica o histórica o fines estadísticos,
sin perjuicio de la aplicación de las medidas técnicas y
organizativas apropiadas que impone el presente Reglamento a
fin de proteger los derechos y libertades del interesado
(«limitación del plazo de conservación»).
- Tratados de tal manera que se garantice una seguridad
adecuada de los datos personales, incluida la protección contra
el tratamiento no autorizado o ilícito y contra su pérdida,
destrucción o daño accidental, mediante la aplicación de medidas
técnicas u organizativas apropiadas («integridad y
confidencialidad»).
- El tratamiento sólo será lícito si se cumple al menos una de las
siguientes condiciones:
- El interesado dio su consentimiento para el tratamiento de sus
datos personales para uno o varios fines específicos;
- El tratamiento es necesario para la ejecución de un contrato en el
que el interesado es parte o para la aplicación a petición de este
de medidas precontractuales;
- El tratamiento es necesario para el cumplimiento de una
obligación legal aplicable al responsable del tratamiento;
- El tratamiento es necesario para proteger intereses vitales del
interesado o de otra persona física;
- El tratamiento es necesario para el cumplimiento de una misión
realizada en interés público o en el ejercicio de poderes públicos
conferidos al responsable del tratamiento;
- El tratamiento es necesario para la satisfacción de intereses
legítimos perseguidos por el responsable del tratamiento o por un
tercero, siempre que sobre dichos intereses no prevalezcan los
intereses o los derechos y libertades fundamentales del
interesado que requieran la protección de datos personales, en
particular cuando el interesado sea un niño.
- Condiciones para el consentimiento:
- Cuando el tratamiento se base en el consentimiento del
interesado, el responsable deberá ser capaz de demostrar que
aquel consintió el tratamiento de sus datos personales.
29
- Si el consentimiento del interesado se da en el contexto de una

de fácil acceso y utilizando un lenguaje claro y sencillo. No será
vinculante ninguna parte de la declaración que constituya
infracción del presente Reglamento.
- El interesado tendrá derecho a retirar su consentimiento en
cualquier momento. La retirada del consentimiento no afectará a
la licitud del tratamiento basada en el consentimiento previo a su
retirada. Antes de dar su consentimiento, el interesado será
informado de ello. Será tan fácil retirar el consentimiento como
darlo.
- El tratamiento de los datos personales de un niño se considerará lícito
cuando tenga como mínimo 16 años. Si es inferior, será lícito si el titular
de la tutela del niño lo autoriza. Los Estados miembros podrán
establecer por ley una edad inferior a tales fines, siempre que no sea
inferior a 13 años.
- Queda prohibido el tratamiento de los datos personales sensibles de
una persona física. No será de aplicación con autorización o por
necesidades vitales.
- Si los fines para los cuales un responsable trata datos personales no

Normalización y desnormalización:
- Normalización: Eliminación de dependencias entre atributos que
originen anomalías en la actualización de los datos y, proporcionar una
estructura más regular para la representación de las tablas.
- Desnormalización: Técnica que consiste en introducir redundancia
deliberada en una base de datos previamente normalizada para
mejorar el rendimiento de las consultas.
Dependencias funcionales:
Un atributo Y se dice que depende funcionalmente de otro X si, y sólo si, a
cada valor de X le corresponde un único valor de Y
- Completa: Un atributo Y tiene dependencia funcional completa
respecto de otro X, si depende funcionalmente de él en su totalidad.
- Transitiva: Un atributo depende transitivamente de otro si, y sólo si,
depende de él a través de otro atributo.
Formas normales según métrica:
- 1FN: Una entidad está en esta forma si no tiene grupos repetitivos. Un
atributo sólo puede tomar un único valor de un dominio simple.
- 2FN: Si cumple con la 1a y, todos los atributos que no forman parte de
las claves candidatas tienen dependencia funcional completa respecto
de éstas.
- 3FN: Si está en la 2a y, todos sus atributos no principales dependen
directamente de la clave primaria (no hay dependencias funcionales
transitivas de atributos no principales respecto de las claves).

- 5FN: Si está en 4FN y, cada relación de dependencia de reunión (join),

Modelo entidad-relación extendido según métrica:
Describe con un alto nivel de abstracción la distribución de datos
almacenados en un sistema. Se compone de:
- Entidad: Objeto, real o abstracto, acerca del cual se desea almacenar
información en la base de datos. Encontramos las fuertes/regulares
(pueden existir por sí solas) y, las débiles (requieren de las fuertes).
Una tabla es una entidad, cada fila es una ocurrencia (instancia, tupla,
registro).
- Relación: Asociación existente entre una o varias entidades. Existen
regulares y débiles, éstas últimas se dividen en la dependencia de
existencia (las ocurrencias dependen de las de la entidad regular) y, la
de identificación (no se identifica sólo por sus atributos). Una relación
es exclusiva cuando la existencia de una relación entre dos tipos de
entidades implica la no existencia de las otras relaciones. Una relación
se caracteriza por:
- Nombre: Lo identifica unívocamente.
- Tipo de correspondencia (cardinalidad máxima): es el número
máximo de ocurrencias de cada tipo de entidad que pueden
intervenir en una ocurrencia de la relación que se está tratando.
Tipos de relaciones:
- 1:1. Cada ocurrencia de una entidad sólo se relaciona con
otra de otra entidad (Un empleado tiene un único correo
corporativo).
- 1:N. Cada ocurrencia de una entidad se relaciona con 0, 1
o varias de otra (Un departamento tiene muchos
empleados, pero cada uno pertenece a un sólo
departamento).
- M:N. Cada ocurrencia de una entidad se relaciona con 0, 1
o varias de otra entidad y viceversa. (Varios alumnos se
matriculan en varios cursos).
39
- Cardinalidad: Representa la participación en la relación de cada
una de las entidades afectadas.
- Dominio: Conjunto nominado de valores homogéneos (mismo tipo),
que puede tomar un atributo. Tiene existencia propia con
independencia de cualquier entidad, relación o atributo.
- Atributo (campo): Propiedad de un tipo de entidad. Unidad básica de
información para identificar la entidad. Puede ser univaluado (un valor
para todas las ocurrencias del tipo de entidad al que pertenece) u
obligatorio (al menos un valor para todas y cada una de las ocurrencias
del tipo de entidad al que pertenece). Es una columna de la tabla.
- Generalización: Permite abstraer un tipo de entidad superior
(supertipo), a partir de varios tipos de entidad (subtipos). Los atributos y
relaciones de los subtipos se asignan al supertipo.
- Especialización: Operación inversa a la generalización. Un supertipo
se compone de varios o un subtipo. Los cuales heredan los atributos y
relaciones del supertipo.
- Categoría: Subtipo que aparece como resultado de la unión de varios
tipos de entidades.
- Agregación: Construir un nuevo tipo de entidad como composición de
otros y su tipo de relación para manejarlo en un nivel de abstracción
mayor.
- Asociación: Relacionar dos tipos de entidades que normalmente son
de dominios independientes, pero coyunturalmente se asocian.
- Jerarquía: Existencia de supertipos y subtipos en uno o varios niveles.

Desnormalización controlada del modelo físico de datos que se aplica para

Diagrama de flujo de datos (DFD) según Métrica:
Ofrece un modelo lógico de procesos que represente el sistema, con
independencia de las restricciones físicas del entorno. Es de estructura.
- Entidad externa: Ente ajeno al sistema que proporciona o recibe
información del mismo.
- Proceso: Funcionalidad que tiene que llevar a cabo el sistema para
transformar o manipular datos.
- Almacén de datos: Información en reposo utilizada por el sistema
independientemente del sistema de gestión de datos, también para la
ejecución del proceso.
- Flujo de datos: Establece la comunicación entre los procesos y los
almacenes de datos o las entidades externas.
Se incorporan:
- Proceso de control: Procesos que coordinan y sincronizan las
actividades de otros procesos del diagrama de flujo de datos.
- Flujo de control: Flujo entre un proceso de control y otro proceso. El
flujo de control que sale de un proceso de control activa al proceso que
lo recibe y el que entra le informa de la situación de un proceso.
Tenemos:
- De consulta: Utilización de los valores de uno o más campos de
un almacén o la comprobación de que los valores de los campos
seleccionados cumplen unos criterios determinados.
- De actualización: Alteración de los datos de un almacén como
consecuencia de la creación de un nuevo elemento.
- De diálogo: Flujo entre un proceso y un almacén que representa
una consulta y una actualización.
Su construcción se basa en el principio de descomposición o explosión de
distintos niveles de detalle:
- Descomposición por niveles de arriba abajo (top-down): se
comienza en el nivel más general y se termina en el más detallado,
pasando por los niveles intermedios necesarios. Disponiendo de un
conjunto de particiones que facilitan su estudio.
43
- La explosión de cada proceso de un DFD origina otro DFD y es
necesario comprobar que se mantiene la consistencia de información
entre ellos.
- Proceso primitivo: Proceso que no requiere de descomposición.

Arquitectura de servicios web REST:
Es stateless (sin estado), cliente-servidor, las respuestas se pueden guardar
en caché, emplea los métodos HTTP: GET, POST, PUT, DELETE, PATCH y
sus códigos de estado. Soporta los formatos JSON y XML, definidos en la
cabecera Content-Type. Al ser un sistema por capas, permite proxies,
balanceadores o gateways. Cualquier dato, objeto o servicio es accesible
mediante una URI global. Multiplataforma. Otras cabeceras utilizadas son
accept, authorization y cache-control. Una API de REST, o API de RESTful,
es una interfaz de programación de aplicaciones que se ajusta a los límites de
la arquitectura REST. Documentación mediante Swagger u OpenAPI.
Autenticación mediante JSON Web Tokens (JWT), OAuth2.0 o básica en
cabecera HTTP. RESTful significa que se cumple con las restricciones de la
arquitectura REST.
Arquitectura de servicios web SOAP:
Reemplaza a XML-RPC, comunicación de mensajes XML en una dirección
entre dos objetos sin estado. Aporta extensibilidad mediante WS-Security
(seguridad) o WS-Routing (ruta), bajo TCP puede usarse sobre cualquier
protocolo de aplicación y permite cualquier modelo de programación. Un
mensaje consta de un sobre que lo envuelve, incluyendo una cabecera
opcional (metadatos), y un cuerpo obligatorio (solicitud o respuesta).

Arquitectura ANSI-SPARC:
- Las vistas no alteran las demás.
- Oculta los detalles físicos del almacenamiento al usuario.
- Se deben cambiar las estructuras de almacenamiento sin afectar las
vistas.
- La estructura interna de la base de datos no se alterará tras cambios en
el aspecto físico del almacenamiento.
Tres niveles:
- Externo: Vista de la base de datos que tienen los usuarios finales.
- Conceptual: Estructura lógica global de la base de datos.
- Interno: Representación en el almacenamiento físico.
Tres esquemas:
- Externo: Diferentes vistas externas de los datos. Puede haber varios.
- Conceptual: Datos y las relaciones entre ellos. Sólo uno por cada base
de datos.
- Interno: Contiene los métodos de representación, los campos de datos
e índices. Solo hay un esquema interno por cada base de datos.
Arquitectura de microservicios:
Una aplicación se construye como un conjunto de pequeños servicios
independientes. Cada servicio se dedica a una funcionalidad del negocio, se
ejecuta en su propio proceso y se comunica con los demás mediante
mecanismos ligeros (API REST, HTTP). Es posible utilizar diferentes
lenguajes de programación y tecnologías dentro de cada uno, además de
gestionarse su propia base de datos.
Deben ser diseñados con tolerancia a fallos:
- Tiempos de espera máximos:
- Reintento al finalizar.
- Encolar para reintentar.
- Disyuntores: Mecanismo para dejar de llamar a un servicio que está
fallando repetidamente y así evitar un fallo en cascada que tumbe todo
el sistema.
- Redundancia.
Manejo de procesos de negocio que involucran a varios servicios con:
- Orquestación: Un software que guíe y dirija el proceso.
- Coreografía: Dejar que cada parte del sistema realice su trabajo y se
les deje trabajar en los detalles.
Como contras añade complejidad y latencia de red.

- Botnet: Red de equipos infectados por un atacante remoto. Quedan a

- Troyano: Se oculta tras un programa aparentemente legítimo para

- Virus: Requiere de un programa en el que alojarse.
- Rootkit (encubridor): Obtiene privilegios de usuario root de forma

Tipos de ataques:
- Pretexting: Escenario falso (creíble), para ganarse la confianza de la
víctima. Base de cualquier ataque de ingeniería social.
- Phishing: Busca engañar a las personas haciéndose pasar por una
autoridad legítima para que revelen información confidencial.
- Quid pro quo: Se trata de obtener información sensible a cambio de
algo.
- Shoulder surfing: Observar las contraseñas/datos sensibles
directamente de la pantalla.
- Dumpster diving: Obtener datos sensibles de documentos
desechados.
- Vishing: Estafa de ingeniería social por teléfono en la que, a través de
una llamada, se suplanta la identidad de una empresa, organización o
persona de confianza, con el fin de obtener información personal y
sensible de la víctima.
- Smishing: Mensajes de texto fraudulentos para obtener información
sensible.
- Whaling: Ingeniería social que engaña a la víctima haciéndose pasar
por un líder de la empresa, un socio de confianza o un colega.
- Pharming: Sitios web maliciosos que aparentan ser legítimos.
- Denegación de servicio (DoS): Interrumpe el funcionamiento normal
de un servicio o sistema informático, saturándolo con múltiples
solicitudes, quedándose inaccesible para los usuarios legítimos.
- Denegación de servicio distribuido (DDoS): En este caso múltiples
dispositivos participan en el ataque.
- Ingeniería social: Técnicas utilizadas para manipular a las personas y
obtener información confidencial o realizar acciones que comprometan
la seguridad. Haciéndose pasar por autoridades de confianza.
- Tailgating o piggybacking: Colarse en unas instalaciones con acceso
restringido, se puede paliar con una esclusa anti-tailgating (mantrap),
(sala intermedia entre dos puertas).
- Día cero: Aprovecha una vulnerabilidad de seguridad desconocida en
un software o hardware, antes de que el proveedor pueda crear y
distribuir un parche o solución.
- Cadena de suministro: Ciberataque que se dirige a una organización
a través de sus proveedores o socios.
52
- Watering Hole: Infectar sitios web que la organización objetivo visita

- Defacement: Alterar la apariencia de la web de forma no autorizada.
- Man in the Middle: Un atacante se interpone entre dos partes que

- Man in the mobile: Obtiene el acceso de un teléfono para interceptar

- Gemelo malvado (Evil twin): Punto de acceso malicioso con mejor

- KRACK (Key Reinstallation Attack): El objetivo del ataque es el

Tipos de RAID (Redundant Array of Disks):
- 0: Mirroring (división), mínimo 2 discos. Cap.máx = disco+peq *
nºunidades.
- 1: Striping (espejo), mínimo 2 discos. Cap.máx =
(disco+peq*nºunidades)/2.
- 2: Datos entrelazados a nivel de bit. El código de error se calcula con el
código de Hamming.
- 3: División de datos a nivel de bytes con un disco de paridad. Mín 3
discos. Tasas de transferencias muy altas.
- 4: IDA (acceso independiente con discos dedicados a la paridad).
División a nivel de bloques con un disco de paridad dedicado. Mín. 3
discos.
- 5: Striping con paridad a nivel de bloques distribuidos por todos los
discos, mínimo 3 discos. Cap.máx = tamaño+peq*(nºunidades-1).
Soporta el fallo de 1 disco.
- 6: Striping con doble paridad a nivel de bloques distribuidos por todos
los discos, mínimo 4 discos. Cap.máx = tamaño+peq*(nºunidades-2).
Soporta el fallo de 2 discos.

- 100 (10+0): División de una división de espejos.

Ethernet (IEEE802.3):
Trama ethernet:
- Preámbulo: 64 bits. Sincronización de relojes de emisor y receptor.
- SFD: 8 bits. Fin de sincronización e inicio de la trama.
- MAC origen: 48 bits.
- MAC destino: 48 bits.
- Tipo de contenido: 16 bits.
- Datos: 46 a 1500 bytes.
- FCS: 32 bits. Control de errores.
El tamaño máximo de una trama es de 1518 bytes, tramas mayores se
denominan jumbo frames, el mínimo es de 64 bytes, de tamaño menor son
consideradas colisiones, ambos casos extremos serían descartados. También
deben ser múltiplos de 8 bits. Los jumbo frames en ipv4 tienen una carga útil
de 9.000 bytes y 4GB en ipv6.
VLAN (IEEE802.1Q “dot1q”):
Etiqueta de 4 bytes que se introduce en una trama:
- TPID (Tag Protocol Identifier): 2 bytes, valor 0x8100 para indicar trama
802.1Q.
- TCI (Tag Control Information): 2 bytes, divididos en:
- PCP (Priority Code Point): 3 bits para calidad de servicio
(prioridad).
- DEI (Drop Eligible Indicator): 1 bit (antes CFI), indica tramas
elegibles para descartar en congestión.
- VID (VLAN Identifier): 12 bits, define la VLAN ID.
Términos:
- VLAN (Virtual LAN): Identificador lógico para el aislamiento de redes.
- VLAN nativa: VLAN que transporta tráfico (tramas), sin etiquetar
(untagged), en un puerto troncal (trunk). En los dispositivos cisco, la
VLAN nativa por defecto es la VLAN 1, la cual no se puede eliminar ni
renombrar.
- Trunk (tagged): Puerto habilitado para el etiquetado (tagged), de tráfico
(tramas), de la VLAN.
63
- Access: (untagged): Puerto que no etiqueta el tráfico y que sólo acepta
una VLAN, asegurando que solo se comuniquen los dispositivos finales
dentro de su segmento de red designado.
- Encapsulación: Proceso de añadir una etiqueta (tag), a las tramas
Ethernet para identificar a qué VLAN pertenecen. Necesario para el
enrutamiento inter-VLAN entre puertos trunk.
- dot1q: Método de encapsulación más común en VLAN. Añade 4 bytes
al encabezado ethernet. El valor del campo EtherType se cambia a
0x8100 para señalar el cambio en el formato de la trama, esto cambia
la trama, forzando un recálculo del campo FCS.

verificar el resultado.
- Caja negra o funcional: Se comprueban las entradas y salidas
verificando que el resultado es el esperado.
- Integración: Comprobar el funcionamiento de conjuntos de
componentes o subsistemas entre ellos.
- Incremental: Arriba-abajo, abajo-arriba o combinadas.
- No incremental: Se prueban de forma individual y después todos
de una vez (Big-Bang).
- Del sistema: Probar el sistema en su conjunto y con otros sistemas
con los que se relaciona.
- Implantación: Funcionamiento correcto del sistema integrado de
hardware y software en el entorno de operación.
- Aceptación: Cumple con las expectativas del usuario para el
funcionamiento esperado y, con el catálogo de requisitos.
- Regresión: Eliminar el efecto onda, para que los cambios de un
componente no provoquen errores en otros.
- Rendimiento: Comprobación de los tiempos de respuesta.

Árboles binarios:
- Recorridos:
- Preorden: Raíz, izquierdo, derecho.
- Inorden: Izquierdo, raíz, derecho.
- Postorden: Izquierdo, derecho, raíz.
- El grado es el máximo de hijos de todos sus nodos. En este caso
siempre será de 2, ya que es el número máximo de hijos que puede
tener un nodo en este tipo de árbol.
- El nivel será la profundidad máxima de cualquier nodo en el árbol,
contando desde la raíz (nivel 0).
- La altura es la longitud de la ruta más larga entre el nodo raíz y
cualquiera de las hojas.
- Una hoja es un nodo que no tiene hijos.
- Estará equilibrado si entre todos sus nodos hoja no hay una diferencia
mayor de un nivel.
- Estará lleno si cada nodo tiene cero o dos hijos y estando estos en el
mismo nivel, con excepción de la raíz.
- Estará vacío si no contiene ningún nodo, ni siquiera uno raíz. Su altura
será 0.
- Estará completo si todos los nodos tienen dos hijos, excepto las hojas,
que irán de izquierda a derecha.

Patrones de diseño GoF (Gang Of Four):
- Creacionales (para problemas de creación de instancias):
- Factory Method: Interfaz para crear objetos en una superclase,
permitiendo a las subclases alterar el tipo de objetos que se
crearán.
- Abstract Factory: Producir familias de objetos relacionados sin
especificar sus clases concretas.
70
- Builder: Producir tipos y representaciones de un objeto a partir
del mismo.
- Prototype: Copiar objetos existentes sin dependencia de las
clases.
- Singleton: Una instancia de acceso global para una clase.
- Estructurales:
- Adapter: Colaboración entre objetos con interfaces incompatibles.
- Bridge: División de una clase grande o grupo relacionado en dos
jerarquías.
- Composite: Componer objetos en estructuras de árbol para
trabajarlas como si fueran objetos individuales.
- Decorator: Añadir funcionalidades a objetos encapsulándolos.
- Facade: Interfaz simplificada a una biblioteca, framework u otros
grupos de clases.
- Flyweight: Compartir partes comunes de varios objetos,
ahorrando RAM.
- Proxy: Sustituto de posición para otro objeto.
- De comportamiento:
- Chain of Responsibility: Solicitudes por una cadena de
manejadores, que decidirán si la pasan al siguiente.
- Command: Solicitud en un objeto independiente que contiene
toda la información.
- Iterator: Recorrer elementos de una colección sin exponer su
representación.
- Mediator: Reducir dependencias caóticas entre objetos.
Restringiendo las comunicaciones directas, colaborando a través
de un objeto mediador.
- Memento: Guardar y restaurar el estado previo de un objeto sin
revelar los detalles de su implementación.
- Observer: Definir un mecanismo de suscripción para notificar a
varios objetos sobre cualquier evento que le suceda al
observado.
- State: Alterar el comportamiento de un objeto cuando cambia su
estado interno, como si cambiara de clase.
- Strategy: Permite definir una familia de algoritmos, cada uno con
clase separada y hacer sus objetos intercambiables.
- Template Method: Define el esqueleto de un algoritmo en la
superclase, permitiendo que las subclases cambien pasos del
algoritmo sin cambiar su estructura.
- Visitor: Separar algoritmos de los objetos sobre los que operan.

- CREATE: Crea objetos en la base de datos (tablas, vistas…).

- ORDER BY: Ordena los resultados de forma ascendente (ASC) o

- OFFSET: Omite un número específico de registros.
- SET: Asigna nuevos valores a columnas.
- VALUES: Define los valores.
- JOIN: Combina datos de múltiples tablas según una condición.
- INNER JOIN: Devuelve los registros que tienen
coincidencias en ambas tablas.
- LEFT JOIN: Devuelve todos los registros de la tabla
izquierda y los coincidentes de la tabla derecha. Si no hay
coincidencia, se muestran valores NULL en el lado
derecho.
- RIGHT JOIN: Devuelve todos los registros de la tabla
derecha y los coincidentes de la tabla izquierda. Si no hay
coincidencia, se muestran valores NULL en el lado
izquierdo.
- FULL JOIN: Devuelve todos los registros cuando hay una
coincidencia en la tabla izquierda o en la derecha. (LEFT +
RIGHT JOIN).
- CROSS JOIN: Devuelve el producto cartesiano de ambas
tablas, combinando cada fila de la primera tabla con todas
las filas de la segunda.
- SELF JOIN: JOIN de una tabla consigo misma, tratándola
como dos tablas distintas (usualmente con alias) para
comparar filas dentro de la misma tabla.
- UNION: Combina resultados de múltiples consultas (eliminando
duplicados).
- UNION ALL: Combina resultados de múltiples consultas
(incluyendo registros duplicados).

- NOT EXISTS: Contrario a EXISTS.

Arquitecturas de hardware:
- Harvard: Una memoria para datos y otra para instrucciones + E/S +
UAL.
- Von Neuman: Una memoria principal + E/S + CPU.
La unidad de control es uno de los tres principales bloques en los que se
divide una CPU:
- Recuento o contador de programa (CP) o registro de control de
secuencia (RCS): Contiene permanentemente la dirección de memoria
de la siguiente instrucción a ejecutar.
- Acumulador: Almacena temporalmente resultados aritméticos y
lógicos para la ALU.
- Registro de instrucción (RI): Contiene la instrucción que se está
ejecutando en cada momento.
84
- Decodificador (D): Interpreta la instrucción para su posterior proceso.
- Reloj (R): Sucesión de impulsos eléctricos a intervalos constantes, que
marcan los instantes en los que han de comenzar los distintos pasos de
los que consta cada instrucción.
- Secuenciador (S) o controlador: Genera microordenes que,
sincronizadas con el reloj, hacen que se vaya ejecutando la instrucción
que está cargada en el registro de instrucción.
Filosofías de diseño de cpus:
- CISC (x86): Muchas instrucciones complejas que suelen ejecutarse en
varios ciclos que realizan múltiples operaciones. Menor tamaño de
código, mayor retrocompatibilidad y programación más sencilla en
ensamblador.
- RISC (ARM/MIPS/SPARC/PowerPC/RISC-V/LoongArch): Pocas
instrucciones simples ejecutadas idealmente en un ciclo que realizan
un tipo de operación. Mayor velocidad, cpus más fáciles de diseñar,
económicas con menor consumo energético.
- EPIC (Explicitly Parallel Instruction Computing, IA-64): Usada en los
intel Itanium, es una interpretación de VLIW (Very Long Instruction
Word), le dice al compilador qué instrucciones pueden ejecutarse en
paralelo (en grupos de 128 bits).
Actualmente algunos procesadores CISC integran RISC.
Taxonomía de Flynn:
- SISD (Single Instruction Single Data): Un solo procesador ejecuta una
única instrucción a la vez sobre un solo dato.
- SIMD (Single Instruction Multiple Data): Una única instrucción se aplica
simultáneamente a múltiples elementos de datos.
- MISD (Multiple Instruction Single Data): Múltiples instrucciones operan
sobre un único flujo de datos.
- MIMD (Multiple Instruction Multiple Data): Múltiples procesadores
ejecutan instrucciones diferentes sobre datos diferentes de forma
independiente. Dos grupos según memoria:
- SMP (Symmetric Multi Processor): Todas las CPU comparten la
misma memoria, acceso de memoria uniforme (UMA).
- MPP (Massively Parallel Processor): Cada CPU tiene su propia
memoria. La comunicación se realiza a través de una red.

las aplicaciones locales y las remotas. NetBIOS, RPC, SIP. (Datos).
- Capa 6 (presentación): Transforma el formato de los datos y
proporciona una interfaz estándar para la capa de aplicación. Cifrado y
descifrado de datos. SSL/TLS. (Datos).
- Capa 7 (aplicación): Responsable de los servicios de red para las
aplicaciones. HTTP, FTP, SMTP, POP3/IMAP, DNS, DHCP, Telnet, SSH.
(Datos).
Modelo TCP/IP:
- Capa 1 (acceso al medio): Los protocolos sólo actúan como máximo
hasta la red local a la que está conectado un host cualquiera.
Direcciones MAC. (Trama).
- Capa 2 (internet): Enrutamiento. Direccionamiento e identificación del
host mediante el sistema de direccionamiento IP jerárquico. (Paquete).
- Capa 3 (transporte): Tiene 2 tipos de conexiones y son orientadas a la
conexión (TCP), o no orientado a la conexión (UDP). Los protocolos de
esta capa pueden proporcionar control de errores, segmentación,
control de flujo, control de congestión y direccionamiento de
aplicaciones. (Segmento).
- Capa 4 (aplicación): Protocolos utilizados por la mayoría de las
aplicaciones para proporcionar servicios de usuario o intercambiar
datos de aplicaciones a través de las conexiones de red establecidas
por los protocolos de las capas inferiores. FTP, HTTP… (Datos).

- Módem: Capa 3. Dispositivo que se conecta a internet.
- Hub (concentrador): Capa 1. Reenvía tráfico de red a otros dispositivos

- Bridge (puente): Capa 2. Conecta dos segmentos de red que empleen

Segmento TCP:
- Puerto origen: 16 bits.
- Puerto destino: 16 bits.
- Número de secuencia: 32 bits. Primer byte del segmento.
- Acuse de recibo: 32 bits. Siguiente número de secuencia del segmento.
- Longitud de cabecera: 4 bits. Tamaño de la cabecera en palabras de 32
bits.
- Reservado: 3 bits. Uso futuro.
- Flags: 9 bits.
- Tamaño de ventana: 16 bits. Tamaño de recepción del buffer. Control de
flujo.
- Suma de verificación: 16 bits. Comprobación de errores.
- Puntero Urgente: 16 bits. Bytes desde el número de secuencia que
indican dónde acaban los datos urgentes.
- Opciones: Características extra.
- Relleno: Para acabar en múltiplos de 32 bits.

- Puerto de origen: 16 bits. (opcional).

Subnetting:
Segmentación de las redes en subredes, las ventajas son un incremento de la
seguridad, proveer a cada departamento únicamente de las herramientas que
necesiten y, evitar que la congestión de un departamento afecte a toda la red.
IP de red: Dirección IP que no puedo asignar a ningún equipo y, que permite
representar en una sola IP todos los equipos de una red. Todos los bit de host
están al valor de 0.
IP de difusión (broadcast): No puede asignarse a ningún equipo de una red,
porque está reservada como dirección IP de destino de todos los equipos de
dicha red. Todos los bit de host están al valor de 1.

Algoritmos de planificación de procesos:
- FCFS (First-Come, First-Served): Peor rendimiento, tras ejecutarse un
proceso y finalizar, se pasa al siguiente.
- SJF (Shortest Job First): Prioriza los procesos más cortos, en caso de
que sean iguales, se comporta como el anterior. Puede ocurrir que los
más largos nunca se ejecuten (inanición).
- SRTF (Short Remaining Time Next): Expulsa procesos largos para
ejecutar otros cortos, puede que nunca llegue a ejecutar el largo.
- Round Robin: Algoritmo circular que asigna un tiempo a cada proceso
y, los va ejecutando con la misma prioridad.
Algoritmos de ordenamiento:
- Burbuja (Bubble Sort): Compara pares de elementos adyacentes y los
intercambia si están en orden incorrecto, repitiendo el proceso hasta
que no se necesiten más intercambios. O(n²).
- Selección (Selection Sort): Busca repetidamente el elemento mínimo
del segmento no ordenado y lo coloca al principio. O(n²).
117
- Inserción (Insertion Sort): Se toma un elemento y se compara con los
ya ordenados, deteniéndose cuando se encuentra un elemento menor,
quedando los mayores una posición a la derecha. O(n²).
- Quick Sort: Elige un elemento del conjunto (pivote), sitúa los demás
elementos alrededor de este y ordena recursivamente las subpartes.
O(n log n).
- Merge Sort: Divide el array en mitades las ordena recursivamente y las
combina. O(n log n).
- Heap Sort: Construye un heap y extrae repetidamente el elemento raíz.
O(n log n).
- Radix Sort: Ordena enteros procesando sus dígitos de forma
individual. O(nk).
- Bucket Sort: Distribuye todos los elementos entre un número finito de
casilleros. O(n).
Algoritmos de teoría de grafos:
- Dijkstra: Encuentra el camino más corto desde un nodo a todos los
demás sólo si los pesos no son negativos.
- Bellman-Ford: Encuentra caminos más cortos desde un nodo origen
incluso con pesos negativos (detecta ciclos negativos).
- Prim: Encuentra el árbol de expansión mínima (MST) de un grafo.
- Kruskal: Encuentra el árbol de expansión mínima (MST) usando un
enfoque basado en conjuntos disjuntos (union-find).
- Floyd-Warshall: Encuentra caminos más cortos entre todos los pares
de nodos (grafos ponderados).
- Kosaraju o Tarjan: Encuentra componentes fuertemente conexos en
un grafo dirigido.

Elementos de programación:
TAD (Tipos abstractos de datos):
- Tupla: Colección ordenada de elementos no editable.
- Lista: Colección ordenada de elementos en la que el orden importa y
permite elementos repetidos.
- Diccionario o mapa: Colección no ordenada de pares clave-valor.
- Conjunto (set): Colección no ordenada de elementos sin duplicar.
- Vector (array): Conjunto de valores (del mismo tipo), ordenados y
operaciones con acceso rápido por índice.
- Registro (struct): Conjunto ordenado de elementos no necesariamente
del mismo tipo.
- Pila: Estructura ordenada LIFO (Last In First Out).
- Cola: Estructura ordenada FIFO (First In First Out).
- Grafo: Conjunto de nodos y arcos que establecen relaciones entre los
nodos. Tipos:
- Dirigido: Conexiones con un sentido. A -> B.
- No dirigido: Conexiones bidireccionales. A <---> B.
- Ponderado: Aristas con valores (distancia, coste).
- No ponderado: Aristas sin valores.

Condicionales:
- if: Si pasa esto (verdadero), ejecuta lo contenido:
if(condición)
{
// Código a ejecutar si la condición es verdadera
}
- if-else: Si pasa esto (verdadero), ejecuta lo contenido, si no, esto otro:
if(condición)
{
// acciones a ejecutar si condición es true
}
else
{
// acciones a ejecutar si condición es false
}
- else-if: Permite evaluar múltiples condiciones en secuencia. Si la
primera condición es falsa, se evalúa la siguiente, y así sucesivamente.
if(condición1)
{
// acciones si condición1 es verdadera
}
else if(condición2)
{
// acciones si condición1 es falsa y condición2 es verdadera
}
else if(condición3)
{
// acciones si condición1 y 2 son falsas, y condición3 es
verdadera
}
else
{
// acciones si todas las condiciones anteriores son falsas
}
- for: Repetir un bloque de código un número definido de veces o
recorrer elementos de una colección:
for (inicialización; condición; actualización)
{
// código que se repite mientras condición sea verdadera
}
126
- while: Ejecuta un bloque de código repetidamente mientras una
condición sea verdadera, se comprueba con cada iteración:
while(condición)
{
// código que se repite mientras condición sea verdadera
// algo dentro debe cambiar la condición para evitar bucle infinito).
}
- do-while: Ejecuta el bloque de código una vez y comprueba la
condición para volver a iterar o terminar:
do
{
// código que se ejecuta al menos una vez
// luego se repite mientras condición sea verdadera
} while(condición);
- switch: Evalúa una expresión y ejecuta el bloque de código
correspondiente al valor que coincida (caso):
switch(expresión)
{
case valor1:
// código a ejecutar si expresión == valor1
break; // sale del switch
case valor2:
// código a ejecutar si expresión == valor2
break;
case valor3:
// código a ejecutar si expresión == valor3
break;
default:
// código a ejecutar si ningún case coincide (opcional)
break;
}
En algunos lenguajes como lua o pascal existe el do until, se ejecutará al
menos una vez hasta que la condición deje de ser falsa.
